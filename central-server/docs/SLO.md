# SLO / SLA 정의 (차수 15 #229)

> 비영리 커뮤니티 풀 특성상 **SLA(계약)는 두지 않고**, 운영 품질 목표인 **SLO** 만 정의한다.
> 실제 추론은 자원봉사 프로바이더 PC 가 수행하므로, 가용성/지연의 상당 부분은 **풀의 기여 상황**에
> 종속된다(통제 범위 명시).

## 통제 구분
- **중앙 서버 통제**: 라우팅·정책·큐잉·메트릭·API 응답.
- **풀 종속(부분 통제)**: 추론 지연·성공률(프로바이더 PC 성능/온라인 여부).

## SLO (목표, 30일 롤링)
| 지표 | 목표 | 측정 |
|---|---|---|
| 중앙 API 가용성(`/actuator/health` UP) | ≥ 99.0% | 헬스 폴링(`ops_healthcheck.sh`, `central ops audit`) |
| 라우팅 처리 성공률(풀에 가용 프로바이더 있을 때) | ≥ 95% | `ai_request` 상태 집계 |
| `/ask` p95 응답(라우팅+추론, 풀 정상 시) | ≤ 10s | Micrometer `http_server_requests` / 요청 로그 |
| 프로바이더 0명(풀 다운) 누적 시간 | ≤ 1%/월 | `providerpool_active_connections` == 0 구간 |

## 에러 버짓 / 대응
- 가용성 99% → 월 ~7시간 다운 허용. 초과 시 원인분석(RUNBOOK) 후 재발방지.
- "풀 0명"은 SLA 위반이 아니라 **기여 부족 신호** → 프로바이더 모집/안내(알림 #220/#164 가 트리거).

## 비목표(Non-goals)
- 개별 요청 응답 보장·환불·우선지원 등 **계약성 약정 없음**(비금전·자원봉사 모델).
- 특정 모델/품질 보장 없음(프로바이더가 제공하는 모델에 의존).

## 관측 연계
- 대시보드/메트릭: `/api/metrics/pool`, `/api/dashboard/{guild}/usage-trend`, Prometheus, Grafana.
- 알림: 풀 오프라인/저용량/프로바이더 오프라인(#220/#163/#164).
