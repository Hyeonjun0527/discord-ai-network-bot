# 콘텐츠 안전 정책 — SSOT

> 결정(2026-06-07): NEXA 는 **중개 플랫폼**이다(모델 제공자 아님). 사전 전면 검열은 하지 않되,
> **중개자로서의 최소 책임**(서버 관리자 책임 명시 + 신고 대응 + 불법 red-line + 디스코드 ToS)은 다한다.
> ⚠ 런칭 전 불법 콘텐츠 대응(특히 CSAM 신고 의무)은 **법률 검토 필수** — 이 문서는 설계 SSOT 일 뿐 법률 자문 아님.

## 1. 입장 — 왜 "전면 검열 X, 무통제도 X"

- **전면 검열 불필요**: 우린 모델을 팔지 않는다. 서버 관리자가 자기 서버 페르소나·콘텐츠를 자기 책임으로 정한다.
- **무통제는 위험**(서비스 생존·법):
  1. **디스코드 ToS = 생존** — 우리 봇이 부적절 콘텐츠(특히 미성년 성적물)를 내면 Discord 가 **NEXA 앱 자체를 밴**. 서비스 사망.
  2. **불법 무관용** — CSAM 등은 중개자 면책이 안 되는 형사 영역.
  3. **플랫폼 책임(통지-삭제)** — safe harbor 면책은 "신고 받으면 대응"이 전제(EU DSA 등 규제 추세).

## 2. 위협 표면

| # | 표면 | 위험 |
|---|------|------|
| 1 | 전역 프롬프트셋 / 채널 AI constitution | 관리자가 유해 페르소나 작성 |
| 2 | RAG 문서 | 유해 텍스트 업로드 → AI 인용 |
| 3 | AI 출력 | **로컬 모델(BYOLLM)은 검열 보장 X** — 무검열 모델 흔함 |

**핵심 난점**: 기부자 로컬 모델을 신뢰할 수 없으므로 "모델이 알아서 거른다"에 의존 불가. 통제는 **NEXA(중앙)** 가 해야 신뢰 가능.

## 3. 제어 레이어 (방어 깊이)

| 레이어 | 내용 | v1 |
|--------|------|----|
| ① NEXA 강제 가드레일 | 관리자 프롬프트 *위에* 끌 수 없는 안전 지침(불법·미성년 성적·혐오·폭력 거부). 프롬프트 구조: NEXA 지침 → 서버 프롬프트 → 질문 | **포함(백엔드)** |
| ② 입력 모더레이션 | 전역 프롬프트·RAG **등록 시** 분류 스크리닝 → 위반 거부/검수 | 선택(후속) |
| ③ 출력 모더레이션 | 답변을 디스코드로 보내기 전 **central 에서** 분류 차단(모델 무관, 가장 확실) | 후속(비용·지연) |
| ④ 신고 + 디스코드 AutoMod | 멤버 신고 → 관리자/NEXA 대응(차단·제거) + 서버 AutoMod 보조 | **포함** |

> ③ 출력 검사는 반드시 **central** 에서(기부자 PC 면 우회 가능). central 이 답변을 중계하므로 그 길목에서 가능.

## 4. 책임 모델 (red-line)

- **콘텐츠 책임 = 서버 관리자**(약관·UI 명시).
- **불법 red-line = NEXA 무관용**: CSAM 등 명백 불법은 자동 차단·신고(법적 의무). 관리자 설정과 무관.
- **디스코드 ToS 준수**: 성인물은 연령 제한 채널 등 Discord 규칙을 따른다.
- **NEXA 글로벌 봇 프로필**: NEXA 운영자 소유(서버 관리자 권한 밖).

## 5. v1 적용 (프로토타입 반영 / 백엔드 Gap)

- **프로토타입(완료)**: 관리 → **안전 탭**(콘텐츠 정책 안내 + 신고 큐 무시/숨김). 전역 프롬프트·RAG 탭에 "콘텐츠 책임=서버 관리자" 안내.
- **백엔드 Gap-Safety(신규 필요)**:
  - ① 가드레일: `/ask` 시스템 프롬프트 최상위에 NEXA 안전 지침 주입(전역 프롬프트보다 우선).
  - ④ 신고: 멤버 신고 수집 → 관리 안전 탭 노출 → 조치(숨김/차단)·감사. (기존 `preset_report`·`AiQualityFeedback` 패턴 확장)
  - red-line 자동 차단(CSAM 등): 출력 경로에 최소 분류(②/③의 부분집합) — 법률 검토 후 우선 도입.
  - 현재 `ProviderSafetyService` 는 자원 보호(과부하)만 — **콘텐츠 모더레이션은 없음**.
