# 콘텐츠 안전 정책 — SSOT

> 결정(2026-06-07): NEXA 는 **중개 플랫폼**이다(모델 제공자 아님). 사전 전면 검열은 하지 않되,
> **중개자로서의 최소 책임**(서버 관리자 책임 명시 + 신고 대응 + 불법 red-line + 디스코드 ToS)은 다한다.
> ⚠ 런칭 전 불법 콘텐츠 대응(특히 CSAM 신고 의무)은 **법률 검토 필수** — 이 문서는 설계 SSOT 일 뿐 법률 자문 아님.

## 1. 입장 — 왜 "전면 검열 X, 무통제도 X"

- **전면 검열 불필요**: 우린 모델을 팔지 않는다. 서버 관리자가 자기 서버 페르소나·콘텐츠를 자기 책임으로 정한다.
- **무통제는 위험**(서비스 생존·법):
  1. **디스코드 ToS = 생존** — 우리 봇이 부적절 콘텐츠(특히 미성년 성적물)를 내면 Discord 가 **NEXA 앱 자체를 밴**. 서비스 사망.
  2. **불법 무관용** — CSAM 등은 중개자 면책이 안 되는 형사 영역.
  3. **플랫폼 책임(통지-삭제)** — safe harbor 면책은 "신고 받으면 대응"이 전제(EU DSA 등 규제 추세).

## 2. 위협 표면

| # | 표면 | 위험 |
|---|------|------|
| 1 | 전역 프롬프트셋 / 채널 AI constitution | 관리자가 유해 페르소나 작성 |
| 2 | RAG 문서 | 유해 텍스트 업로드 → AI 인용 |
| 3 | AI 출력 | **로컬 모델(BYOLLM)은 검열 보장 X** — 무검열 모델 흔함 |

**핵심 난점**: 기부자 로컬 모델을 신뢰할 수 없으므로 "모델이 알아서 거른다"에 의존 불가. 통제는 **NEXA(중앙)** 가 해야 신뢰 가능.

## 3. 제어 레이어 (방어 깊이)

| 레이어 | 내용 | v1 |
|--------|------|----|
| ① NEXA 강제 가드레일 | 관리자 프롬프트 *위에* 끌 수 없는 안전 지침(불법·미성년 성적·혐오·폭력 거부). 프롬프트 구조: NEXA 지침 → 서버 프롬프트 → 질문. **`/ask` 모든 경로(채널 AI 커스텀·채널 프로필·설정 없는 기본 서버)에 항상 주입** — 설정 없는 기본 서버는 NEXA 기본 정체성(니아)으로 답한다. | **포함(백엔드)** |
| ② 입력 모더레이션 | 전역 프롬프트·RAG **등록 시** 분류 스크리닝 → 위반 거부/검수 | 선택(후속) |
| ③ 출력 모더레이션 | 답변을 디스코드로 보내기 전 **central 에서** 분류 차단(모델 무관, 가장 확실) | 후속(비용·지연) |
| ④ 신고 + 디스코드 AutoMod | 멤버 신고 → 관리자/NEXA 대응(차단·제거) + 서버 AutoMod 보조 | **포함** |

> ③ 출력 검사는 반드시 **central** 에서(기부자 PC 면 우회 가능). central 이 답변을 중계하므로 그 길목에서 가능.

### 3-1. 가드레일·기본 페르소나 전문 비공개

NEXA 강제 가드레일(①)과 builtin 기본 페르소나(니아) **전문은 클라이언트(웹·데스크톱 앱)로 내려보내지 않는다**.
영업(페르소나 카피)·안전(가드레일 우회 연구 차단)상 비공개이며, **F12(개발자 도구)로도 전문을 확인할 수 없어야 한다**.

- 클라이언트에는 **preview(요약)** 또는 **자리표시자**만 노출한다. builtin 셋은 `preview` 만 전송하고 `content`(전문)는 전송하지 않는다(사용자 작성 셋만 전문 반환).
- 실제 LLM 실행 프롬프트에는 가드레일/페르소나 **전문이 그대로** 들어간다. 마스킹은 *사용자에게 보이는 미리보기 응답에서만* 적용한다.
- 구현:
  - 가드레일 자리표시자 — `ContentSafety.GUARDRAIL_PUBLIC_PLACEHOLDER`, 마스킹 헬퍼 `ContentSafety.maskGuardrail()`.
  - 채널 AI 프롬프트 미리보기 — `ChannelAiCustomizationController.promptPreview` 가 응답 `systemPrompt` 에 `maskGuardrail()` 적용(실행 경로 `AskCommandHandler` 는 미적용).
  - 전역 프롬프트셋 API(`serverPrompts`, 신설 예정) — builtin/가드레일 셋은 `preview` 만 반환하도록 구현.
  - 프로토타입 미러 — `prototypes/desktop` 의 builtin 니아 셋은 `preview` 만 보유(전문 없음), `renderProfileTab` 가 🔒 비공개 배지로 표시.

## 4. 책임 모델 (red-line)

- **콘텐츠 책임 = 서버 관리자**(약관·UI 명시).
- **불법 red-line = NEXA 무관용**: CSAM 등 명백 불법은 자동 차단·신고(법적 의무). 관리자 설정과 무관.
- **디스코드 ToS 준수**: 성인물은 연령 제한 채널 등 Discord 규칙을 따른다.
- **NEXA 글로벌 봇 프로필**: NEXA 운영자 소유(서버 관리자 권한 밖).

## 5. v1 적용 (프로토타입 반영 / 백엔드 Gap)

- **프로토타입(완료)**: 관리 → **안전 탭**(콘텐츠 정책 안내 + 신고 큐 무시/숨김). 전역 프롬프트·RAG 탭에 "콘텐츠 책임=서버 관리자" 안내.
- **백엔드 Gap-Safety(신규 필요)**:
  - ① 가드레일: `/ask` 시스템 프롬프트 최상위에 NEXA 안전 지침 주입(전역 프롬프트보다 우선).
  - ④ 신고: 멤버 신고 수집 → 관리 안전 탭 노출 → 조치(숨김/차단)·감사. (기존 `preset_report`·`AiQualityFeedback` 패턴 확장)
  - red-line 자동 차단(CSAM 등): 출력 경로에 최소 분류(②/③의 부분집합) — 법률 검토 후 우선 도입.
  - 현재 `ProviderSafetyService` 는 자원 보호(과부하)만 — **콘텐츠 모더레이션은 없음**.

## 6. 법률 검토 시뮬레이션 (2026-06-07, AI 법률가 페르소나 — 자문 아님)

> ⚠️ 아래는 역할극 분석이며 **실제 법률 자문이 아니다.** 관할·사실관계로 결론이 달라진다.
> **출시 전, 특히 CSAM 대응은 반드시 변호사 검토.**

### 우선순위 액션
| 우선 | 항목 | 조치 |
|---|---|---|
| **P0** | CSAM | 처리 경로 최소 탐지(해시 매칭) + 삭제 + **수사기관/NCMEC 신고 절차**. 변호사 검토 필수 |
| **P0** | 약관(ToS/AUP/개인정보처리방침) | 책임=서버 관리자, 금지행위, 신고·제재, 면책, 준거법·관할 |
| **P0** | 신고-조치 체계 | 신고 창구 + 처리 기록·기한(DSA/망법 통지-조치) |
| **P1** | AI 고지 | 니아가 AI/봇임을 명확히(EU AI Act 투명성) — 외형 고정으로 충족 |
| **P1** | 개인정보 흐름 고지 | "질문이 기부자 PC 로 전달" 명시 + 기부자 로그 금지 약관 |
| **P1** | 미성년자 | 성인 콘텐츠는 디스코드 연령 제한 채널 한정 |
| **P2** | 저작권 | RAG 업로드 책임=관리자 + 통지-조치(+미국 향하면 DMCA 대리인) |

## 7. 도관 항변(mere conduit) 분석

"라우팅만 한다 / 못 보면 면책 / SSL 회사처럼" 주장에 대한 검토:
- **사전 검열 안 함 = 정당**(일반 감시 의무 없음 — DSA Art.8·§230·망법). 사전 전면 검열 불필요·권장.
- **"안 봄"≠"못 봄"**: 평문 라우팅은 "안 보기로 선택"일 뿐. 진짜 면책엔 기술적 접근 불가가 필요. 단 **의도적 무지(willful blindness)** 는 특히 CSAM 에서 가중 사유.
- **SSL 비유는 부정확**: SSL 은 트래픽이 통과하지 않고 콘텐츠와 무관. 우리는 트래픽이 봇을 통과하고 **AI 서비스 자체를 운영**(페르소나·RAG·전역 프롬프트 환경 제공) → 순수 도관 약함(Roommates.com 법리).
- **CSAM 은 도관 항변·암호화로도 탈피 불가**(형사·신고의무).
- **성인 이미지(SD)**: 생성은 기부자 PC(중개면 책임 약화)나, "이미지 요청 받기" 기능 제공으로 관여도↑ → 방조 여지. 연령 제한 채널 한정 + 책임=관리자 + 미성년/비동의 딥페이크 red-line(성폭력처벌법 가중).

## 8. 데이터 처리 모델 — "진짜 E2E 불가 → 무저장(no-retention)" (2026-06-07 결정)

**디스코드 봇 구조상 유저↔모델 진짜 E2E 는 불가능**(유저가 일반 디스코드 클라이언트, 메시지가 디스코드 평문,
봇이 평문 수신). 대신 **"처리는 하되 보유·기억하지 않음"** 으로 실질 목표 달성. 데이터 범주 분리:

| 데이터 | 성격 | 처리 |
|---|---|---|
| **유저 질문/답변(대화)** | 흐르는 트래픽 | **무저장·무로깅·메모리 즉시 폐기**. DB 기록 X. **provider 로그 보존 금지(약관)** |
| **전역 프롬프트·채널 AI·프리셋** | 서버 관리자 설정 | 기능상 보유 → **at-rest 암호화**, 우리 관리 |
| **RAG 문서** | 서버 관리자 업로드 | 색인 위해 보유 → at-rest 암호화, 등록 책임=관리자 |

- 유저 대화 **무보유** → 개인정보·GDPR 리스크 급감 + 도관 항변 강화(대화에 한해).
- 기능 설정/RAG 는 유저 대화와 **다른 범주** → 관리 기능과 충돌 없이 보유·암호화.
- **CSAM red-line 해시 스캔**은 무저장과 별개로 처리 경로(특히 이미지)에 둔다 — "보관"이 아니라 "통과 시 해시 대조"라 무저장과 양립, willful blindness 회피.
- **백엔드 Gap-Privacy(신규)**: 라우팅 핫패스 무로깅 보장·메모리 폐기 / 설정·RAG at-rest 암호화 / provider 약관에 로그 금지 / 이미지 경로 CSAM 해시 스캔.

## 9. "무저장은 책임 회피인가?" — 아니다 (2026-06-07)

- **무저장 = 데이터 최소화**: 개인정보보호법·GDPR 의 핵심 원칙("필요 없는 데이터는 보관하지 마라")의 모범.
  안 가질수록 유출·오남용 리스크가 0 에 수렴 — 갖는 게 오히려 부담. Signal 등 프라이버시 서비스 표준.
- **회피가 되는 경계는 하나**: **의도적 무지(willful blindness)** — 책임을 피하려 *일부러* 못 보게 설계하고
  *불법을 알면서 방조*하는 경우(FOSTA/SESTA). 우리는 "필요 없어서 안 갖되 **인지하면 대응**" → 정당.
- **무저장이어도 이행하는 의무**(그래서 회피 아님): ① 신고 대응(통지-조치) ② CSAM 처리 중 탐지·신고
  ③ 수사기관 영장·보존명령 협조(무저장 정책이 영장 거부 근거가 되지 않음).
- **결정적**: 메시지 **원본은 디스코드에 그대로 존재**. 우리가 안 가져도 신고 시 메시지 ID 로 확인·삭제 가능,
  증거는 디스코드 보유 → "데이터를 없애 책임 회피"가 **물리적으로 성립 불가**. 우리만 안 가질 뿐.

## 10. 백엔드 책임 체크리스트 (구현 SSOT)

| # | 책임 | 상태 |
|---|------|------|
| B1 | 유저 콘텐츠(프롬프트/응답) **DB 무저장** | ✅ 충족 — ai_request/usage_log/contribution_log 메타데이터만(콘텐츠 컬럼 없음) |
| B2 | 라우팅 핫패스 **무로깅** | ✅ 충족 — 프롬프트/응답 미로깅, agent 로그 스크럽, Sentry send-default-pii:false |
| B3 | 처리 후 **메모리 즉시 폐기** | ✅ 충족 — ProviderSession.pending future 완료 시 cleanup |
| B4 | provider 약관에 **로그 보존 금지** 명시 | 약관(P0) + 앱 약관 안내 반영 |
| B5 | 서버 설정·프롬프트·RAG 문서 **at-rest 암호화** | ✅ 구현 — EncryptedStringConverter(AES-GCM·점진·레거시호환), 키 NEXA_FIELD_ENC_KEY |
| B6 | 이미지 경로 **CSAM 해시 스캔** | 변호사 검토 후(P0) |
| B7 | **신고 수집·조치·감사** | 진행 중(관리 안전 탭, Gap-Safety) |
| B8 | **영장·보존명령 협조 절차** | 운영 절차(문서) |
| B9 | **AI 고지**(니아가 봇/AI 임을 명확히) | ✅ 충족(외형 고정·BOT 표시) |
