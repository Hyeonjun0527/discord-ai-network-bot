# NEXA 데스크톱 — 유저 플로우 인벤토리 (프로토타입 검증 대상)

> 프로토타입(`prototypes/desktop/`)이 검증해야 할 **모든 유저 흐름·상태**의 SSOT.
> 목표: "설치 직후 첫 유저"부터 "제공 중인 기존 유저"까지, 모든 분기·엣지를 PROTO 컨트롤러로 점프해 확인 가능.
> 근거: `provider-agent/src/provider_agent/webui.py`(GUI/온보딩), central-server onboarding(OAuth/승인).
>
> 체크박스 = 프로토타입 구현 여부. `[x]` 구현됨 / `[ ]` 미구현.

---

## 앱 Stage 상태머신

```
[onboarding] ──연동하기──▶ [connect] ──토큰발급──▶ [main]
   A1~A4                    B1~B3                   D (현재)
                              │
                              ├─ 승인 대기 ─▶ [main:pending]
                              └─ 취소/후보없음 ─▶ [onboarding] 복귀
```

PROTO 컨트롤러는 `stage`와 각 stage의 `sub-state`를 직접 점프할 수 있어야 한다.

---

## A. 온보딩 마법사 (첫 유저) — `stage: onboarding`

- [ ] **A1 환영/안내** — Ollama·이미지 생성·자동 연결 소개. `[나중에]`(스킵→main, 토큰없음) / `[시작하기]`
- [ ] **A2 런타임 선택** — `Ollama 설치(권장)` · `Stable Diffusion(선택)` · `지금은 설치 안 함` 체크
- [ ] **A3 동작 방식** — 토글 4개: 로그인 시 자동 실행 · 로그인 후 자동 연결 · 이미지 요청 받기 · 백그라운드 유지
- [ ] **A4 요약/완료** — 선택 요약 → `[메인 화면으로]`(토큰없음) / `[연동하기]`(→ connect)

## B. Discord 연결 — `stage: connect`

- [ ] **B1 로그인 유도** — OAuth 활성: `[Discord 로그인]`(브라우저 전환) / 비활성: `고급 · 토큰 붙여넣기`
- [ ] **B2 서버 선택** — 후보 분기:
  - [ ] 후보 **0개** — "봇이 있는 서버 중 참여 가능한 곳 없음" 안내
  - [ ] 후보 **1개** — 자동 선택(화면 생략)
  - [ ] 후보 **N개** — 서버 카드 리스트에서 선택
- [ ] **B3 결과 분기**:
  - [ ] 자동 승인 → 토큰 발급 → `main` 연결 완료
  - [ ] **승인 대기**(autoApprove=false) → `main:pending` (관리자 승인 후 토큰)
  - [ ] **취소**(Discord에서 거부) → onboarding 복귀 + 안내
  - [ ] 토큰 입력 경로 — 관리자가 준 `/provider-join TOKEN` 붙여넣기

## C. 런타임 준비 (온보딩 중·후 어디서나)

- [ ] **C1 Ollama 미설치** — `Ollama 자동 설치 + 기본 모델` 버튼 → 진행률(brew/winget → serve → pull)
- [ ] **C2 Ollama 설치됨·데몬 꺼짐** — `Ollama 시작 + 기본 모델` 버튼
- [ ] **C3 SD 설치 마법사** — 모델 선택(SD1.5 4GB / SDXL 6.6GB) → 진행률(clone → 모델 다운 → 기동 → ready)

## D. 메인 (사용 중) — `stage: main` *(현재 프로토타입)*

- [x] **D1 제공 상태** — 정상 / 일시중지 / 문제(연결 끊김) + 진단
- [x] **D2 연결된 서버 목록** — 권한 배지(관리자/기부자), 상태(연결됨/일시중지/승인 필요), 아바타 폴백
- [x] **D3 런타임 카드** — Ollama/SD 상태 + ⋯ 메뉴(연결 점검·열기·설정·관리)
- [ ] **D4 main:pending** — 승인 대기 중 상태(연결 안 됨, "관리자 승인을 기다리는 중")
- [ ] **D5 모델 변경 → 재연결** — 모델 토글 후 `변경 적용(재연결)` 안내
- [ ] **D6 백그라운드 실행 중** — "이 창은 설정용, 백그라운드가 이미 연결됨" 안내

## E. 엣지/상태

- [ ] **E1 한도 초과(LIMITED)** — 일일 한도 도달 → 다음날 리셋 안내
- [ ] **E2 자원 보호 일시중지** — 배터리<20% 또는 CPU>85% → 자동 일시중지
- [ ] **E3 재설치/재페어링** — durable 토큰으로 모든 서버 자동 재연결 / 없으면 재로그인
- [ ] **E4 런타임 미준비 경고** — 이미지 수신 ON인데 SD 미준비 등 경고 칩

## F. 권한 분기

- 관리자(Server Admin) — provider 승인/거절·정책은 **중앙 웹 대시보드**(앱이 아님). 앱에선 자기 서버에 `관리자` 배지로 표시.
- 기부자(Provider User) — 데스크톱 앱에서 자기 PC 리소스(Ollama/SD)만 제어.

## 구현 순서(제안)

1. PROTO 컨트롤러 → **stage 네비게이터**로 확장(onboarding/connect/main + sub-state 점프)
2. **A 온보딩 4단계** (가장 앞 흐름)
3. **B 연결·승인 분기** (0/1/N, 자동/대기/취소)
4. **C 런타임 설치 마법사**(진행률)
5. **D4~D6 + E 엣지 상태**

각 단계 구현 시 이 문서의 체크박스를 갱신한다.
