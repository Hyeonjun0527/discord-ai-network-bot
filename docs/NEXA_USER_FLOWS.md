# NEXA 데스크톱 — 유저 플로우 인벤토리 (프로토타입 검증 대상)

> 프로토타입(`prototypes/desktop/`)이 검증해야 할 **모든 유저 흐름·상태**의 SSOT.
> 목표: "설치 직후 첫 유저"부터 "제공 중인 기존 유저"까지, 모든 분기·엣지를 PROTO 컨트롤러로 점프해 확인 가능.
> 근거: `provider-agent/src/provider_agent/webui.py`(GUI/온보딩), central-server onboarding(OAuth/승인).
>
> 체크박스 = 프로토타입 구현 여부. `[x]` 구현됨 / `[ ]` 미구현.

---

## 앱 Stage 상태머신

```
[onboarding] ──연동하기──▶ [connect] ──토큰발급──▶ [main]
   A1~A4                    B1~B3                   D (현재)
                              │
                              ├─ 승인 대기 ─▶ [main:pending]
                              └─ 취소/후보없음 ─▶ [onboarding] 복귀
```

PROTO 컨트롤러는 `stage`와 각 stage의 `sub-state`를 직접 점프할 수 있어야 한다.

---

## A. 온보딩 마법사 (첫 유저) — `stage: onboarding`

- [x] **A1 환영/안내** — Ollama·이미지 생성·자동 연결 소개. `[나중에]`(스킵→main, 토큰없음) / `[시작하기]`
- [x] **A2 런타임 선택** — `Ollama 설치(권장)` · `Stable Diffusion(선택)` · `지금은 설치 안 함` 체크
- [x] **A3 동작 방식** — 토글 4개: 로그인 시 자동 실행 · 로그인 후 자동 연결 · 이미지 요청 받기 · 백그라운드 유지
- [x] **A4 요약/완료** — 선택 요약 → `[메인 화면으로]`(토큰없음) / `[연동하기]`(→ connect)

## B. Discord 연결 — `stage: connect`

- [x] **B1 로그인 유도** — OAuth 활성: `[Discord 로그인]`(브라우저 전환) / 비활성: `고급 · 토큰 붙여넣기`
- [x] **B2 서버 선택** — 후보 분기:
  - [x] 후보 **0개** — "봇이 있는 서버 중 참여 가능한 곳 없음" 안내
  - [x] 후보 **1개** — 자동 선택(화면 생략)
  - [x] 후보 **N개** — 서버 카드 리스트에서 선택
- [x] **B3 결과 분기**:
  - [x] 자동 승인 → 토큰 발급 → `main` 연결 완료
  - [x] **승인 대기**(autoApprove=false) → `main:pending` (관리자 승인 후 토큰)
  - [x] **취소**(Discord에서 거부) → onboarding 복귀 + 안내
  - [x] 토큰 입력 경로 — 관리자가 준 `/provider-join TOKEN` 붙여넣기

## C. 런타임 준비 (온보딩 중·후 어디서나)

- [x] **C1 Ollama 미설치** — `Ollama 자동 설치 + 기본 모델` 버튼 → 진행률(brew/winget → serve → pull)
- [x] **C2 Ollama 설치됨·데몬 꺼짐** — `Ollama 시작 + 기본 모델` 버튼
- [x] **C3 SD 설치 마법사** — 모델 선택(SD1.5 4GB / SDXL 6.6GB) → 진행률(clone → 모델 다운 → 기동 → ready)

## D. 메인 (사용 중) — `stage: main`

> 각 항목의 **트리거(언제 발생)** 를 명시한다. 트리거 없이 화면만 정의하면 모호해진다.

- [x] **D1 제공 상태** — 정상/일시중지/문제/승인대기/한도/자원보호 + 진단.
  **트리거**: 앱 자체 상태 변화(연결·일시중지·한도 등) 또는 사용자 토글(일시중지/재개).
- [x] **D2 연결된 서버 목록** — 권한 배지·상태·아바타 폴백. **트리거**: 진입 시 로드.
  카드 클릭 → **서버 상세(G)** 진입.
- [x] **D3 런타임 카드** — 실행 중/꺼짐/미설치 + 시작/설치 + ⋯ 메뉴. **트리거**: 런타임 상태 변화.
- [x] **D4 승인 대기(pending)** — "관리자 승인을 기다리는 중". **트리거**: 서버 연결 시 autoApprove=false.
- [x] **D5 모델 변경 → 재연결** — `변경 적용`. **트리거**: **사용자가 02 모델 화면에서 모델 토글/기본 변경 후 `변경 적용` 클릭**(여기가 유일 트리거).
- [x] **D6 백그라운드 실행 중** — 연결 핀 `백그라운드 제공 중`(클릭 토글). **트리거**: 백그라운드 서비스 연결 여부.

## E. 엣지/상태

- [x] **E1 한도 초과(LIMITED)** — 한도 도달 안내 + `한도 늘리기`. **트리거**: 일일 처리 한도 도달.
- [x] **E2 자원 보호 일시중지** — 배터리<20% 또는 CPU>85% → 자동 일시중지. **트리거**: 시스템 자원 임계 초과(자동).
- [x] **E3 재설치 자동 재연결** — durable 토큰으로 승인된 모든 서버 자동 재연결(재로그인 없이).
  **트리거**: 앱 `첫 실행(시작)` 시점의 자동 이벤트(*사용자 액션 아님*). 단 **조건부**:
  - durable 토큰은 **`~/.config/nexa/config.json`(홈, 0600)** 에 저장 — 앱 바이너리와 분리.
  - **앱만 재설치**(홈 설정 유지) → 토큰 살아있음 → **자동 재연결 O**.
  - **PC 교체·포맷·설정 삭제**(`~/.config/nexa` 소실) → 토큰 없음 → **재로그인(B 온보딩) 폴백**.
  ※ "재로그인 없이 복구"는 *설정 파일 유지* 가 전제. 라벨에서 이 전제를 뭉뚱그리지 말 것.
- [x] **E4 런타임 미준비 경고** — SD 미준비인데 이미지 수신 ON → 카드 메타 경고. **트리거**: 이미지 수신 ON + SD 꺼짐/미설치.
- [x] **E5 런타임 전부 미설치** — Ollama·SD 둘 다 미설치 → "제공할 AI 런타임이 없어요" 안내 배너(설치는 런타임 카드에서).
  **트리거**: 두 런타임 모두 absent.

## D'. 빈 상태(empty)

- [x] **빈 서버 목록** — 연결된 서버 0개 → "아직 연결된 서버가 없어요 · + 서버 추가".
  **트리거**: connections.length == 0 (온보딩 직후·전부 제거). 추가는 `enterServerAdd`(I3 — 로그인 없음).

## G. 서버 상세 (기부자 관점) — `stage: main`, 서버 탭 → 카드 클릭

> **권한 모델(2026-06-07)**: 앱은 기부자 도구. 관리자 정책은 웹 대시보드로 위임.
> 화면정의: `docs/NEXA_DESKTOP_SCREENS.md` 07. 백엔드 Gap-R/S/P/W 는 거기 명시.

- [x] **G1 개요(기부자 관점)** — 내 기여 현황(오늘 요청·제공모델·평균) + 제공 중인 내 모델 칩.
  **트리거**: 서버 카드 클릭 / PROTO 점프.
- [x] **G2 내 제공 토글** — 이 서버에 대한 내 제공 `일시중지/재개`(provider self-service).
  **트리거**: 사용자 클릭. PENDING 서버면 숨김.
- [x] **G3 내 제공 정책** — 하루 한도·동시 처리·최대 시간·공개 대상(`변경` 모달).
  **트리거**: 사용자 클릭. **나에게만 적용**(다른 참여자 무관).
- [x] **G4 권한 분기** — 관리자: `웹 대시보드 열기`(채널AI·RAG·프리셋·다중응답·Provider승인 위임) /
  기부자: "서버 설정은 관리자 권한 필요" 안내. **트리거**: 내 역할(role).
- [x] **G5 승인 대기(PENDING)** — "관리자 승인을 기다리는 중", 정책/토글 숨김. **트리거**: state==PENDING.

## F. 권한 분기

- 관리자(Server Admin) — provider 승인/거절·정책은 **중앙 웹 대시보드**(앱이 아님). 앱에선 자기 서버에 `관리자` 배지로 표시.
- 기부자(Provider User) — 데스크톱 앱에서 자기 PC 리소스(Ollama/SD)만 제어.

## 구현 순서(제안)

1. PROTO 컨트롤러 → **stage 네비게이터**로 확장(onboarding/connect/main + sub-state 점프)
2. **A 온보딩 4단계** (가장 앞 흐름)
3. **B 연결·승인 분기** (0/1/N, 자동/대기/취소)
4. **C 런타임 설치 마법사**(진행률)
5. **D4~D6 + E 엣지 상태**

각 단계 구현 시 이 문서의 체크박스를 갱신한다.
