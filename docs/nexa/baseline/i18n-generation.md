# NEXA i18n generation baseline (T020)

Status: `REVIEW` candidate; depends on T019, which is still `REVIEW` because T017 has a pending human security gate.  
Audit date: 2026-06-20.  
Scope: repository text SSOT, module generated files, desktop prototype i18n table, ignored webui asset copy, and i18n verification wrappers.

## Source of truth

`i18n/messages.json` is the only editable text source for shared user-visible bot/web/agent/desktop strings. All non-private sections must provide `ko`, `en`, and `ja` for every key. New NEXA user-visible text must either:

1. add a key to the correct section in `i18n/messages.json`, then run `make i18n-gen`; or
2. for Discord slash command names/descriptions only, update `central-server/src/main/kotlin/com/discordassistant/central/platform/discord/CommandLoc.kt` and keep its coverage tests green.

Do not edit generated files directly.

## Drift result

`make i18n-gen` was executed in this task. Pre/post SHA-256 hashes for the SSOT and generated bot/web/agent/desktop prototype artifacts were identical, and the generated-file diff was empty. `make i18n-check` and `./scripts/nexa-verify.sh i18n` both reported generated artifacts synchronized and `ko/en/ja` complete.

The local ignored `provider-agent/src/provider_agent/webui_assets/i18n-agent.js` copy was stale before sync. `make sync-desktop` refreshed it from `prototypes/desktop/i18n-agent.js`; after sync the hashes matched and `make desktop-check` passed endpoint/shape/leak guards. This confirms the desktop runtime path is:

```text
i18n/messages.json (desktop section)
  -> make i18n-gen
  -> prototypes/desktop/i18n-agent.js
  -> make sync-desktop
  -> provider-agent/src/provider_agent/webui_assets/i18n-agent.js (ignored generated asset)
```

## Verification commands

- `make i18n-gen` — regenerate bot/web/agent JSON and desktop prototype JS from the SSOT.
- `make i18n-check` — fail on generated drift or missing `ko/en/ja` values.
- `./scripts/nexa-verify.sh i18n` — NEXA wrapper for `make i18n-check`.
- `make sync-desktop` — copy desktop prototype assets, including `i18n-agent.js`, into ignored provider-agent webui assets.
- `make desktop-check` — confirm synced desktop assets have no prototype/mock leakage and still match backend contracts.
- `./scripts/nexa-verify.sh central` — runs central tests including `I18nMessagesDriftTest`, `I18nFallbackTest`, `MessagesTest`, `WebI18nServingTest`, and `CommandLoc*` coverage/drift tests.

T020 adds `i18n` scope to both `scripts/nexa-verify.sh` and `scripts/nexa-verify.ps1` so the SSOT drift guard is addressable from the same task wrapper as docs/central/protocol. This is a small KISS compatibility addition; it delegates to the existing `make i18n-check` rather than duplicating validation logic.

Because T020 depends on T019 and T019 is still dependency-gated `REVIEW`, this task should remain `REVIEW` after automated verification. It can move to `VERIFIED` only after upstream gates are approved or the task graph dependency is revised.
