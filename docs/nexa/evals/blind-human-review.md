# 블라인드 인간 평가 프로토콜 (NEXA-P16-T023)

- 작업: NEXA-P16-T023 (`kind: documentation`, `human_gate: true`) · 상위: [ADR 0007](../../adr/0007-nexa-social-member-context.md)
- 입력: 30일 시뮬레이션([EXP-30day-simulation](../experiments/EXP-30day-simulation.md)) 및
  시나리오 재생([scenario-dsl](scenario-dsl.md))이 만든 **합성 transcript**.
- 사람다움 차원: [human-likeness gate](../../../scripts/nexa-human-likeness-eval.py) 의 약점 축(과보수 IGNORE·
  공감 온도·담백함·AI 말투·타이밍)과 정렬.

## 목적

정책(NEXA)과 사람의 transcript 를 **가명화·블라인드** A/B 로 평가자에게 보여, 자연스러움·방해·일관성·불쾌감을
사람 판단으로 잰다. 정량 metric(FIR/MIR/Brier·분포 distance)이 못 잡는 **질적 사람다움**을 보완한다.

## 윤리 — AI 임을 속이는 실험이 아니다 (acceptance)

**acceptance(T023) — evaluator 에게 연구 목적과 데이터 사용을 고지한다**. 이 프로토콜은 *제품 사용자*를 속여
"AI 가 사람인 척"하게 하는 실험이 **아니다**. 평가자(연구 참여자)는 다음을 사전에 고지받고 동의한다:

- 일부 transcript 는 **AI 정책(NEXA)** 이, 일부는 **사람** 이 만든 것이며, 어느 쪽인지 모르는 **블라인드** 조건에서
  평가한다는 사실.
- 평가 목적은 **AI 응답 품질 연구**이며, 데이터는 합성(운영 사용자 데이터 아님)이라는 사실.
- 평가 결과 사용처(모델 개선·gate 보정)와 보관·파기 정책.
- 언제든 **중단**할 수 있고, 평가 산출물에는 평가자 개인정보가 남지 않는다는 사실.

블라인드는 **평가자에게 라벨을 숨기는 것**(편향 제거)일 뿐, 평가자에게 연구 성격을 숨기는 것이 아니다.

## 데이터 준비 — 가명화

1. **출처 라벨링**: 각 transcript 에 내부적으로 `source ∈ {human, policy}` 와 `model_version` 을 붙인다(평가자 비공개).
2. **가명화**: 실제 닉네임·서버명·고유 식별자를 결정론 가명(actor-A/유저-1/서버-X)으로 치환한다. 합성 fixture 는
   이미 가명이므로 추가 PII 제거가 거의 없다. 운영 데이터는 입력하지 않는다.
3. **표면 단서 제거**: 봇 멘션 표기·시스템 푸터·typing indicator 메타 등 "AI 임을 드러내는 형식 단서"를 통일해
   내용 자체로만 평가되게 한다(형식이 아니라 행동을 본다).
4. **블라인드 배정**: 같은 장면(prompt 맥락)에 대해 human 과 policy 응답을 쌍(A/B)으로 묶고, A/B 순서를
   transcript 마다 무작위(결정론 seed)로 섞어 위치 편향을 제거한다.

## 평가 차원 (1–5 Likert, 각 항목 독립)

| 차원 | 질문 | 약점 매핑 |
| --- | --- | --- |
| 자연스러움 | 이 응답이 사람 멤버의 말처럼 들리는가? | AI 말투·담백함 |
| 방해(낮을수록 좋음) | 대화 흐름을 끊거나 과하게 끼어드는가? | 과반응·점유 |
| 일관성 | 앞 맥락·기억과 모순 없이 이어지는가? | stale memory·상충 |
| 불쾌감(낮을수록 좋음) | 무례·괴롭힘 가담·부적절함이 있는가? | 괴롭힘 경계·공감 온도 |
| 적시성 | 답해야 할 때 답하고, 침묵할 때 침묵했는가? | 과보수 IGNORE·타이밍 |

평가자는 각 transcript 의 출처를 **추측하지 않는다**(블라인드 유지). 출처 추측을 강요하면 "사람 vs 봇 맞히기"
게임이 되어 품질 평가가 오염된다 — 우리는 **품질**을 재지 정체를 맞히게 하지 않는다.

## 평가 절차

1. 평가자 ≥ 3명, 각자 독립적으로 동일 batch 를 평가(상호 비공개).
2. 한 batch = A/B 쌍 N개. 쌍마다 두 응답에 5개 차원 점수를 매긴다.
3. 평가 후에야 출처 라벨을 풀어, 차원별 **human vs policy 점수 차이**와 **평가자 간 합의**(Cohen's kappa,
   [agreement 모듈](../../../ml/social-policy/src/nexa_policy/eval/agreement.py))를 계산한다.
4. 합의가 낮은(kappa < 임계) 항목은 gold 에서 제외하거나 soft label 로 남긴다(P10-T022 규칙 재사용).

## 합격 기준 (gate)

- 윤리 고지·동의 절차가 문서대로 수행됐다(고지 없는 평가 결과는 폐기).
- 블라인드·가명화가 깨지지 않았다(평가자에게 라벨/PII 노출 0).
- 차원별로 policy 가 human 대비 **불쾌감·방해에서 유의하게 나쁘지 않다**(안전 우선). 자연스러움·적시성의
  격차는 약점 리포트([report-template](report-template.md))로 넘겨 개선 추적한다.

## 한계

합성 transcript 는 운영 분포가 아니다. 이 프로토콜은 운영 배포 전 **준비도 점검**이며, 실제 사용자 평가가
아니다. 운영 사용자 대상 평가는 별도 동의·승인 절차가 필요하며 이 작업 범위 밖이다.
