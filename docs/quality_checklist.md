# AI 응답 품질 평가 체크리스트
# AI Response Quality Evaluation Checklist

> 졸업 프로젝트 — Discord AI Assistant  
> 평가자가 직접 수행하는 수동 품질 평가 절차서입니다.

---

## 1. 개요

이 문서는 Discord AI Assistant의 AI 응답을 체계적으로 평가하기 위한 루브릭(rubric)과 테스트 시나리오를 제공합니다.  
평가는 **5점 척도(1=매우 낮음, 5=매우 높음)**를 기준으로 하며, 각 기준에 대한 세부 설명을 포함합니다.

---

## 2. 평가 기준 (Evaluation Criteria)

### 2.1 정확성 (Accuracy)

AI가 제공하는 정보가 채널 대화 원문 또는 객관적 사실과 일치하는지 평가합니다.

| 점수 | 설명 |
|------|------|
| 5 | 모든 사실이 원문과 완전히 일치하며, 추론이 있더라도 근거가 명확함 |
| 4 | 핵심 내용이 정확하고, 사소한 오류 1건 이하 |
| 3 | 대부분 정확하나 2~3건의 불일치 또는 과장이 존재 |
| 2 | 주요 내용에 오류가 있어 신뢰도가 낮음 |
| 1 | 사실과 크게 다르거나, 없는 내용을 생성(hallucination)함 |

---

### 2.2 관련성 (Relevance)

응답이 사용자의 질문 또는 채널 맥락과 얼마나 관련이 있는지 평가합니다.

| 점수 | 설명 |
|------|------|
| 5 | 응답 전체가 질문/맥락에 집중되어 있으며 불필요한 내용 없음 |
| 4 | 핵심은 관련되어 있으나, 약간의 이탈된 내용 포함 |
| 3 | 질문에 부분적으로 답변하나, 중요한 내용이 누락되거나 관련 없는 내용이 포함됨 |
| 2 | 응답이 질문과 크게 동떨어져 있음 |
| 1 | 질문과 전혀 무관한 응답 |

---

### 2.3 간결성 (Conciseness)

응답이 핵심 내용을 불필요한 중복 없이 전달하는지 평가합니다.

| 점수 | 설명 |
|------|------|
| 5 | 간결하고 명확하며, 필요한 정보만 포함 |
| 4 | 대체로 간결하나 약간의 반복 또는 불필요한 설명 존재 |
| 3 | 핵심 내용은 있으나 텍스트가 지나치게 길거나 반복적 |
| 2 | 중요 내용이 불필요한 서술에 묻혀 찾기 어려움 |
| 1 | 응답이 지나치게 길고, 핵심 정보 파악이 불가능 |

---

### 2.4 한국어 품질 (Korean Language Quality)

응답의 한국어 자연스러움, 문법 정확성, 어휘 적절성을 평가합니다.

| 점수 | 설명 |
|------|------|
| 5 | 자연스러운 한국어, 문법 오류 없음, 문어/구어체 상황에 맞게 사용 |
| 4 | 대체로 자연스럽고 문법 오류 1건 이하 |
| 3 | 의사소통은 가능하나 어색한 표현 또는 문법 오류 2~3건 |
| 2 | 어색한 번역투 표현이 많아 읽기 불편함 |
| 1 | 문법 오류가 많고, 의미 파악이 어려운 수준 |

---

### 2.5 완전성 (Completeness)

질문 또는 요청의 모든 측면을 다루었는지 평가합니다.

| 점수 | 설명 |
|------|------|
| 5 | 질문의 모든 측면에 빠짐없이 답변 |
| 4 | 주요 측면은 모두 다루었으나 세부 사항 1~2건 누락 |
| 3 | 핵심 내용 중 일부 누락 |
| 2 | 중요한 내용이 대부분 누락됨 |
| 1 | 질문에 실질적으로 답하지 못함 |

---

## 3. 테스트 시나리오

### 시나리오 A — 채널 요약 정확성 (`/summarize`)

**목적**: `/summarize` 명령의 요약 정확성을 평가합니다.

**준비**:
1. Discord 테스트 채널에 다음 유형의 메시지 30개를 준비합니다.
   - 일반 대화 15개
   - 결정 사항 관련 메시지 5개 (예: "다음 회의는 금요일로 결정!")
   - 액션 아이템 포함 메시지 5개 (예: "@홍길동 PR 리뷰 부탁해요")
   - 주제 변환 메시지 5개

2. `/summarize limit:30` 실행

**평가 항목**:

| 항목 | 기준 | 점수 (1–5) | 비고 |
|------|------|------------|------|
| 주요 주제 추출 | 3개 이상의 주제가 정확히 식별됨 | | |
| 결정 사항 반영 | 5개 결정 사항 중 4개 이상 포함 | | |
| 액션 아이템 반영 | 5개 아이템 중 4개 이상 포함 | | |
| 요약 길이 적절성 | Discord 메시지 2000자 제한 내 | | |
| 한국어 품질 | 위 2.4 기준 적용 | | |

**합계**: _____ / 25

---

### 시나리오 B — Q&A 관련성 (`/ask`)

**목적**: `/ask` 명령의 답변 관련성과 정확성을 평가합니다.

**준비**:
1. 채널에 특정 주제에 관한 대화 20개를 준비합니다.
   - 예시 주제: "팀 프로젝트 일정 논의"
   - 채널에 언급된 날짜, 이름, 결정 사항을 사전에 기록합니다.

2. 다음 질문을 순서대로 실행합니다.
   - Q1: `/ask question:다음 미팅은 언제야?`
   - Q2: `/ask question:프로젝트 담당자가 누구야?`
   - Q3: `/ask question:현재 논의된 기술 스택이 뭐야?`

**평가 항목 (질문당)**:

| 항목 | Q1 | Q2 | Q3 |
|------|----|----|-----|
| 정확성 (1–5) | | | |
| 관련성 (1–5) | | | |
| 완전성 (1–5) | | | |

**합계**: _____ / 45

**테스트 문장**:

| "프로젝트 마감일이 다음 주 수요일입니다." | ja | | | |

**합계**: _____ / 50

## 4. 수동 품질 평가 절차

### 4.1 사전 준비

```bash
# 1. 테스트 환경 확인
# Discord 테스트 서버에 접속 (전용 테스트 채널 사용 권장)

# 2. 봇 실행 확인
python -m discord_assistant
# → 콘솔에 "Logged in as [봇이름]" 확인

# 3. 모델 선택 확인
# /settings → 현재 활성 제공자/모델 확인 후 기록
```

### 4.2 평가 수행 순서

1. **환경 설정 기록**: 평가 시작 전 현재 모델, 제공자, 언어 설정을 기록합니다.
2. **시나리오 A 수행**: 테스트 채널 준비 → `/summarize` 실행 → 결과를 평가 시트에 기록.
3. **시나리오 B 수행**: Q&A 질문 3개를 각각 실행 → 답변을 평가 시트에 기록.
4. **시나리오 C 수행**: 번역 5개를 순서대로 실행 → 결과를 평가 시트에 기록.
5. **시나리오 D 수행**: 자유 대화 3개 프롬프트 실행 → 결과를 평가 시트에 기록.
6. **모델 변경 후 반복**: `/settings`에서 다른 모델로 변경 후 동일 절차 반복.

### 4.3 결과 집계

```
총점 = (시나리오 A 합계 / 25 × 100) × 0.30
     + (시나리오 B 합계 / 45 × 100) × 0.30
     + (시나리오 C 합계 / 50 × 100) × 0.20
     + (시나리오 D 합계 / 60 × 100) × 0.20

목표 총점: ≥ 70점
```

## 5. 합격 기준 (Acceptance Criteria)

| 지표 | 합격 기준 | 비고 |
|------|----------|------|
| 전체 가중 총점 | ≥ 70 / 100 | 필수 |
| 정확성 평균 | ≥ 3.5 / 5 | 필수 |
| 한국어 품질 평균 | ≥ 3.5 / 5 | 필수 |
| Hallucination 발생 횟수 | ≤ 1회 / 세션 | 권고 |
| 완전성 평균 | ≥ 3.0 / 5 | 권고 |
