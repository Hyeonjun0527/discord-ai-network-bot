# 개별 사용자 옵트아웃 모델

- 작업: NEXA-P02-T003 (`human_gate: true`, decision) · 상위: [ADR 0007](../../../docs/adr/0007-nexa-social-member-context.md)
- 근거: [data-categories.md](./data-categories.md), [consent-model.md](./consent-model.md),
  [socialmemory-context.md](../../../docs/nexa/architecture/socialmemory-context.md)

## 결정

길드가 NEXA를 켰더라도, **개별 사용자는 자기 메시지를 NEXA의 관찰·기억·학습에서 제외(opt-out)할
수 있다.** 길드 동의가 개인의 거부를 덮어쓰지 않는다(개인 거부 우선).

### 식별과 흐름

- 옵트아웃 주체 = 메시지 작성자 본인(사용자 ID 기준). 길드 관리자 동의와 별개 레이어.
- UX: 본인이 디스코드에서 직접 거부 의사를 표시(예: 개인 명령/버튼) — 개인 프라이버시 결정이라
  관리자 웹 대시보드가 아니라 **사용자 본인 경로**로 처리한다. 옵트아웃 상태는 가명화 전 사용자
  매핑으로 관리하되 그 자체가 식별 데이터이므로 최소 보관한다.
- 옵트아웃 사용자의 메시지는 conversation 관찰 단계에서 즉시 배제된다(이벤트 정규화 시 필터).

## acceptance 충족

- **옵트아웃 후 신규 파생 데이터가 생성되지 않는다**: 임베딩·관계 상태·학습 산출물 등 어떤 파생도
  새로 만들지 않는다([data-categories.md](./data-categories.md)의 Medium/High 범주 전부).
- **기존 파생 데이터 삭제가 추적된다**: 옵트아웃 이전에 만들어진 파생물(임베딩·관계·기억)은 삭제
  전파(T009) 대상으로 등록되고 제거 진행이 추적된다.

## 불변식

1. 개인 옵트아웃은 길드 동의보다 우선한다(거부가 이긴다).
2. 옵트아웃 사용자의 메시지로는 신규 파생 데이터를 만들지 않는다.
3. 기존 파생 데이터는 삭제 전파로 제거되며 그 진행이 추적 가능하다.
